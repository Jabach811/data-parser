Vendor Data Parser

Field Guide

Drop a de-conversion file set from any of fourteen recordkeepers. The parser works out who sent it, splits it into reports, and hands back a mapped workbook.

The run-through

Three screens, in order.

01  CONFIGURE

Drop the files

Leave the source dropdown alone — the app identifies the vendor from the files themselves. Enter the case number and plan name, then drop everything you have. If a set arrives in pieces, drop the rest later and they join what's already loaded.

02  REVIEW

Check the totals

Grand total, participant count, and lines accepted versus discarded. Anything the parser refused shows up in Discarded Line Detail with a reason. Source and fund totals break the money out by money type and by fund.

03  EXPORT

Map and download

Upload the mapping workbook to validate source and fund codes. Once it passes, export the full workbook — a title page plus one tab per report. Individual reports download on their own too.

Across every vendor

What the parser handles on its own.

It knows who sent it

Filename patterns first, then a look inside the file if the name gives nothing away. It only commits when exactly one vendor matches, so it won't guess wrong — you can always override with the dropdown.

Files can trickle in

For vendors that ship a set, each drop adds to what's already loaded instead of wiping it. The status line names which files you're holding and which are still outstanding.

Packed numbers get unpacked

Fixed-width files store money with no decimal point and the plus-or-minus sign buried in the last character. The parser unpacks all of it — 12456 reads as 124.56, and 1001} reads as −10.01.

Dates come out as dates

Eight digits in, a real date out. No more counting characters to work out whether a field is a birth date or a hire date.

Summary reports reconcile

Where a vendor ships a printed summary alongside the data, the app reads the PDF and compares its plan-level totals against what was parsed, money type by money type.

SSNs are normalized

Stripped to plain digits everywhere, whatever formatting the vendor used. Participant records line up across reports without hand-fixing.

Nothing disappears quietly

Every line is either accepted or discarded with a stated reason. The counts sit at the top of the Review screen so a short file is obvious immediately.

Mapping is enforced

Comparison stays blocked until the mapping workbook passes validation. You can't reconcile against a mapping that hasn't been checked.

Still open

What isn't finished.

The TIAA seven-file set and the John Hancock ten-file set are taken in and tracked, but their field layouts haven't been documented yet — so the app holds the files and reports what's outstanding rather than splitting them into columns. Send the layouts along and both turn into full reports.
